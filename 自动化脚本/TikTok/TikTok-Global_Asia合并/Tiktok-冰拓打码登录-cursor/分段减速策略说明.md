# 分段减速策略说明

## 问题根源

**用户发现的关键问题**：
- ❌ 拖过头后，验证系统**立即判定**
- ❌ 根本**没有时间**执行微调
- ❌ 一次性拖拽必须精确，否则就失败

## 解决方案：分段减速

### 核心思想

**模拟真实人类操作滑块的方式**：
```
人类操作滑块：
1. 开始：快速移动到接近位置
2. 接近：明显减速，小心对齐
3. 最后：慢慢微调到精确位置

机器模拟：
1. 前70%：快速平滑移动（快速接近）
2. 中20%：明显减速60%（小心接近）
3. 后10%：再减速80%，极慢爬行（精确对齐）
```

## 分段策略详解

### 第一段：快速接近（前70%）
```javascript
进度：0% → 70%
速度：正常（100%）
目的：快速到达目标附近

示例：
如果总距离300px
这个阶段移动：210px（70%）
剩余距离：90px
```

### 第二段：明显减速（中20%）
```javascript
进度：70% → 90%
速度：降低到40%（减速60%）
目的：接近目标时小心控制

这个阶段应该移动：60px（20%）
但实际只移动：24px（60px × 40%）
剩余距离：66px

为什么减速？
- 避免冲过头
- 有时间观察位置
- 模拟人类接近目标时的谨慎
```

### 第三段：极慢爬行（最后10%）
```javascript
进度：90% → 100%
速度：降低到20%（再减速80%）
目的：极慢、极精确地到达目标

这个阶段应该移动：30px（10%）
但实际只移动：6px（30px × 20%）
剩余距离：60px → 强制到达终点

为什么极慢？
- 几乎没有惯性
- 精确停在目标位置
- 模拟人类最后的微调动作
```

### 增加总时长
```javascript

现在：4000ms（4秒）

- 给减速留出足够时间
- 让速度变化更明显
- 更像人类操作（人类也会慢慢对齐）
```

### 时间分配
```
总时长：4000ms

前70%：2800ms（正常速度）
中20%：800ms（减速60%，时间不变）
后10%：400ms（再减速80%，时间不变）

效果：
- 同样的时间内移动更少距离 = 速度降低
- 最后400ms只移动很少距离 = 精确停止
```

## 代码实现

### 核心逻辑
```javascript
for (var step = 0; step <= 60; step++) {
    var progress = step / 60;
    var easedProgress;
    
    if (progress < 0.7) {
        // 第一段：快速
        easedProgress = easeInOutCubic(progress / 0.7) * 0.7;
        
    } else if (progress < 0.9) {
        // 第二段：减速60%
        var p = (progress - 0.7) / 0.2;
        easedProgress = 0.7 + (0.2 * p * 0.4);
        
    } else {
        // 第三段：再减速80%
        var p = (progress - 0.9) / 0.1;
        easedProgress = 0.78 + (0.22 * p * 0.2);
    }
    
    var currentX = startX + deltaX * easedProgress;
    path.push([currentX, startY]);
}
```
