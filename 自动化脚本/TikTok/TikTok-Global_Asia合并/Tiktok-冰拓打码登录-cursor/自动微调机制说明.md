# 自动微调机制说明

## 问题背景

**用户反馈**：
- ✅ 滑块可以移动了
- ⚠️ 拖拽超出了缺口位置
- ❌ 但没有自动拖回来

## 解决方案：自动微调

### 工作流程

```
第1步：初次拖拽
    └─ 使用惯性补偿的gesture拖拽
    └─ 可能稍有偏差

第2步：等待2秒观察

第3步：微调检测 ⭐ 新增
    ├─ 重新查找滑块位置
    ├─ 计算当前位置 vs 目标位置
    ├─ 计算偏差
    └─ 判断是否需要微调

第4步：执行微调（如果需要）
    ├─ 如果偏差 ≤ 5px → 无需微调 ✓
    ├─ 如果偏差 6-50px → 执行微调
    └─ 如果偏差 > 50px → 跳过（可能判断错误）

第5步：等待验证
```

## 微调检测逻辑

### 判断标准

```javascript
偏差 = 滑块当前左边缘 - 目标左边缘

if (|偏差| ≤ 5px) {
    ✓ 对齐成功，无需微调
} else if (|偏差| ≤ 50px) {
    ⚠️ 需要微调
    方向 = 偏差 > 0 ? "往左" : "往右"
    距离 = |偏差|
} else {
    ❌ 偏差过大，可能判断错误，跳过
}
```

### 微调动作

```javascript
// 计算微调的起点和终点
起点X = 滑块当前中心点
终点X = 起点X - 偏差

// 如果滑过头（偏差>0），往左拉
// 如果没到位（偏差<0），往右推

// 执行快速小幅度调整
时长 = min(1000ms, |偏差| × 30)
swipe(起点X, 起点Y, 终点X, 终点Y, 时长)
```

## 优势

### 1. 自动纠偏
- ✅ 即使初次拖拽不精确，也能自动调整
- ✅ 不需要手动干预

### 2. 智能判断
- ✅ 只在需要时才执行微调
- ✅ 避免过度调整

### 3. 安全保护
- ✅ 偏差过大时不执行（防止错误操作）
- ✅ 有异常处理机制

### 4. 提高成功率
- ✅ 补偿值不够精确也能成功
- ✅ 多一层保障

## 工作原理图

```
初次拖拽
    ↓
等待2秒
    ↓
[微调检测]
    ├→ 偏差 ≤ 5px → 完美 ✓ → 等待验证
    ├→ 偏差 6-20px → 小幅微调 → 等待验证
    ├→ 偏差 21-50px → 中幅微调 → 等待验证
    └→ 偏差 > 50px → 跳过 → 等待验证
```

## 与惯性补偿的配合

### 双重保障机制

```
第一层：惯性补偿（主动预防）
    └─ 在初次拖拽时就考虑惯性
    └─ 目标 = 理论位置 - 补偿值
    └─ 理想情况下就精确对齐

第二层：自动微调（被动纠正）
    └─ 检测实际结果
    └─ 如果还有偏差，主动调整
    └─ 确保最终对齐
```

### 最佳实践

1. **先优化惯性补偿**
   - 让初次拖拽尽量精确
   - 减少需要微调的频率

2. **微调作为保障**
   - 处理边缘情况
   - 提高整体成功率

## 总结

### 核心思想
**"测量-调整-验证"的闭环**

1. **测量**：检测当前位置
2. **调整**：如果有偏差就微调
3. **验证**：再次检测确认
